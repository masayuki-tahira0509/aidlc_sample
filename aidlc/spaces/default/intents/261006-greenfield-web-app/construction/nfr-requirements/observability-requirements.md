# Observability Requirements — 社内お知らせ掲示板

## Sources

- [requirements] NFR2: ローカル実行。NFR7: 保守性。
- [construction-phase] エラーは呼び出し元に伝播またはログ出力。ログに個人情報・秘密情報を出さない。

## 方針

ローカル・単一利用者・お試し用途のため、メトリクス収集・分散トレーシング・ダッシュボード・アラートは対象外。観測性は「開発・動作確認に必要な最小限のログ」に絞る。 [NFR2]

## 要件一覧

| ID | 要件 | 根拠 |
|----|------|------|
| NFR7-OBS.1 | バックエンドは標準的なロギング（Spring Boot デフォルトの SLF4J/Logback）を用い、起動・主要CRUD操作・エラーをログ出力する。 | [construction-phase][NFR7] |
| NFR7-OBS.2 | ログレベルを区別する。ERROR=回復不能な失敗、WARN=回復可能な異常、INFO=主要イベント（起動・CRUD成功）、DEBUG=診断詳細。 | [construction-phase] |
| NFR7-OBS.3 | ログに個人情報・入力本文の全文・秘密情報を無制限に出力しない（ログ衛生）。エラーログは原因究明に必要な範囲に留める。 | [construction-phase][security NFR-SEC.8] |
| NFR7-OBS.4 | フロントエンドは開発時にブラウザコンソールへエラーを出力する。本番相当の集約基盤は本スコープ外。 | [NFR2] |

## 三本柱の適用範囲

| 柱 | 本アプリでの扱い |
|----|----------------|
| ログ（Logs） | 採用（最小構成）。SLF4J/Logback の標準出力。NFR7-OBS.1〜3 |
| メトリクス（Metrics） | 対象外（単一利用者ローカル。Actuator 等の導入は将来拡張） |
| トレース（Traces） | 対象外（単一サービス・外部連携なし C3） |

## アラート・ダッシュボード

- アラート、ダッシュボード、SLI/SLO 定義は設定しない（ローカル・お試し用途）。

## 明示的な非目標

- 分散トレーシング、メトリクス収集基盤、集中ログ基盤、アラート/ページング、ダッシュボードは本スコープ外。
- ログの長期保持・インデックス化・保持ポリシーは定めない。

## Assumptions & Open Questions

- [assumption] 将来運用に移行する場合は Spring Boot Actuator によるメトリクス公開やログ集約を追加検討（本スコープ外）。
