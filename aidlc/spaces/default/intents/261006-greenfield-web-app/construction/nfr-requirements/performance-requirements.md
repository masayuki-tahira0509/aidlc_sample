# Performance Requirements — 社内お知らせ掲示板

## Sources

- [requirements] NFR6: 操作が明示的UIから行える。NFR9: 件数増加で一覧表示が破綻しない。NFR2: ローカル実行。
- [Q3] 性能目標は緩やかな努力目標のみ。厳密な percentile 基準値は定めない（学習目的）。

## 方針

ローカル・単一利用者・お試し用途のため、性能は「体感で快適」を満たす緩やかな努力目標として定義する。以下の数値は合否を縛る基準ではなく目安であり、Build and Test で厳密計測を強制しない。 [Q3][NFR2]

## 要件一覧（努力目標）

| ID | 対象 | 努力目標 | 条件 | 計測 |
|----|------|---------|------|------|
| NFR6.1 | 一覧表示（お知らせ一覧の初回描画） | 1秒以内を目安 | ローカル・単一利用者・件数 ~数百件まで | 任意（体感確認で可） |
| NFR6.2 | 保存（作成/編集の確定〜一覧反映） | 500ms 以内を目安 | ローカル・単一利用者 | 任意 |
| NFR6.3 | 削除（確定〜一覧反映） | 500ms 以内を目安 | ローカル・単一利用者 | 任意 |
| NFR6.4 | バックエンド CRUD API 応答 | 200ms 以内を目安 | ローカル・ネットワーク転送除く | 任意 |

## リソース・前提

- 単一利用者のローカル実行のため、同時接続・高負荷は想定しない。
- 全件表示（FR1.3）だが、件数が数百件規模までは上記目安を満たす想定。件数が大きく増える場合はスケーラビリティ要件（ページング後付け、NFR9/OQ4）で対応する。

## 明示的な非目標（Anti-Requirements）

- 「速いこと」のような計測不能な目標は設けない。
- 多数同時利用・高スループットの最適化は本スコープ外（単一利用者前提）。
- 厳密な percentile ベースのSLO設定・性能回帰テストの強制は行わない（学習目的、Q3）。

## Assumptions & Open Questions

- [assumption] 上記の数値目安は妥当な初期値であり、実装後に体感を見て調整可能。合否基準には用いない。
- [assumption] 件数が数千件規模に達した場合は NFR9/OQ4 のページング導入を検討する。
