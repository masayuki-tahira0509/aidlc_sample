# Reliability Requirements — 社内お知らせ掲示板

## Sources

- [requirements] NFR1: 再起動後もデータ保持（ファイルベースDB永続化）。NFR2: ローカル実行。
- [construction-phase] 統合境界（DB操作・ファイルI/O）でのエラーハンドリング必須、サイレント失敗禁止。

## 方針

ローカル・単一利用者・お試し用途のため、エンタープライズ級の可用性（多重化・自動フェイルオーバー）やDRは対象外。信頼性要件は「データが失われないこと」と「失敗が握りつぶされないこと」に絞る。 [NFR2]

## 要件一覧

| ID | 要件 | 根拠 |
|----|------|------|
| NFR1.1 | 登録・編集・削除したお知らせは、アプリ再起動後もデータが保持される（H2 ファイルモードで永続化）。 | [NFR1][Q1] |
| NFR1.2 | DB操作・ファイルI/O 等の統合境界では必ずエラーハンドリングを行い、失敗を呼び出し元に伝播またはログ出力する。サイレント失敗を許さない。 | [construction-phase] |
| NFR1.3 | 保存・削除の失敗時は、ユーザーに失敗を明示（エラー状態UI）し、データ不整合を残さない（部分更新を避ける）。 | [refined-mockups Q3=B][construction-phase] |
| NFR1.4 | 回復可能なエラー（一時的なI/O失敗）と致命的エラー（DBファイル破損等）を区別し、前者は再試行余地、後者は明確に失敗させる方針とする。 | [construction-phase] |

## 可用性・回復目標

| 項目 | 本アプリでの扱い |
|------|----------------|
| SLA/SLO | 設定しない（ローカル・単一利用者、お試し用途） |
| 冗長化・フェイルオーバー | 対象外（単一プロセス・ローカル） |
| バックアップ | H2 のDBファイルをコピーすることで手動バックアップ可能（運用手順として任意）。自動バックアップは本スコープ外 |
| RTO/RPO | 厳密目標は設定しない。DBファイルのコピーがあれば手動復旧可能 |

## 明示的な非目標

- 高可用性構成（マルチAZ/マルチリージョン）、自動フェイルオーバー、ゼロダウンタイムデプロイは本スコープ外。
- 継続的バックアップ・DRリハーサルは行わない。

## Assumptions & Open Questions

- [assumption] データ保護は H2 ファイルの手動コピーで足りる想定（お試し用途）。重要運用に移行する場合は定期バックアップを別途検討。
