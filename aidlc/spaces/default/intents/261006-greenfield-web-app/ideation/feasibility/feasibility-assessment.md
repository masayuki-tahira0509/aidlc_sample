# Feasibility Assessment

## Technical Viability

本プロジェクトは技術的に十分実現可能である。社内向けポータル/ダッシュボード型Webアプリは、確立された技術で構築できる定型的なアーキテクチャに該当する。 [desc] [Q1]

### 推奨技術スタック

| レイヤー | 技術 | 根拠 |
|---------|------|------|
| フロントエンド | React | ユーザー指定。SPA/ダッシュボードUIに広く使われる成熟したフレームワーク | [Q5] |
| バックエンド | Java（Spring Boot 推奨） | ユーザー指定。REST API構築のデファクトスタンダードで学習リソースが豊富 | [Q5] |
| データストア | H2（組み込み）または SQLite | 無料・簡易・ローカル動作可能。お試し用途に最適。将来PostgreSQL等へ移行容易 | [Q5] |
| 実行環境 | ローカル（開発者PC） | 手元で動けばよいとの要望 | [Q4] |

### アーキテクチャ概要（仮）

- フロントエンド（React SPA）がバックエンド（Spring Boot REST API）をHTTPで呼び出す2層構成
- バックエンドが軽量DB（H2/SQLite）からコンテンツを取得しJSONで返却
- 認証なし（社内ネットワーク前提） [Q3]
- 外部システム連携なし（スタンドアロン） [Q1]

## Risk Analysis

| リスク | 影響度 | 対策 |
|--------|--------|------|
| React + Java の2言語構成による学習負荷 | 低 | 学習目的のプロジェクトであり、むしろ想定内の学び | [Q5] |
| 認証なしのためアクセス制御が効かない | 低 | 社内ネットワーク限定・お試し用途のため許容範囲 | [Q3] |
| 組み込みDBは本番スケールに不向き | 低 | お試し段階では問題なし。本格運用時にRDBMSへ移行 | [Q4] [Q5] |

## Technical Uncertainty

技術的な不確実性は低い。すべて確立されたパターンで構成され、新規性のある技術課題は存在しない。

## Assumptions & Open Questions

- [assumption] バックエンドフレームワークは Spring Boot を推奨とするが、確定は後続ステージ。
- [assumption] 具体的なDB（H2 / SQLite）は Code Generation で確定する。
- [assumption] ポータルに表示する具体的なコンテンツ種別は Requirements Analysis で確定する。
