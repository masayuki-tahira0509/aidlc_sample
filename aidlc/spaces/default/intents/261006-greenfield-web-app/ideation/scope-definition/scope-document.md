# Scope Document

## プロダクト概要

社内向けの「お知らせ掲示板」Webアプリ。社内のお知らせ・アナウンスを一元的に掲示し、閲覧・管理できるツール。 [Q1]

## In Scope（今回作るもの）

| ID | 機能 | 説明 | Source |
|----|------|------|--------|
| IS-1 | お知らせ一覧表示 | 登録されたお知らせを一覧で閲覧する | [Q1] [Q2] |
| IS-2 | お知らせ新規登録 | 新しいお知らせを投稿する（Create） | [Q2] |
| IS-3 | お知らせ編集 | 既存のお知らせを修正する（Update） | [Q2] |
| IS-4 | お知らせ削除 | 不要なお知らせを削除する（Delete） | [Q2] |

→ **フル CRUD の社内お知らせ掲示板** [Q2]

## Out of Scope（今回は作らないもの）

| ID | 項目 | 理由 | Source |
|----|------|------|--------|
| OS-1 | 認証・ログイン機能 | 社内ネットワーク前提、お試し用途 | [Q3] |
| OS-2 | 外部システム連携 | スタンドアロンで完結 | [Q3] |
| OS-3 | 検索・フィルタ機能 | MVPでは見送り（将来拡張候補） | [Q2] |
| OS-4 | 権限管理・ロール | 認証がないため対象外 | [Q3] |
| OS-5 | 通知機能（メール等） | MVPスコープ外 | [assumption] |

## Minimum Viable Scope

一覧・登録・編集・削除の4機能が揃った、単一エンティティ（お知らせ）のCRUDアプリ。これが動けばMVP成立。 [Q1] [Q2]

## Sequencing Preference

価値優先（まず動くものを最速で）。シンプルなものから着手する。 [Q4]

## 技術的境界（Feasibilityより継承）

- フロントエンド: React / バックエンド: Java（Spring Boot推奨）/ DB: H2・SQLite
- ローカル実行

## Assumptions & Open Questions

- [assumption] お知らせの項目（タイトル・本文・投稿日時・投稿者名など）の具体的なデータ項目は Requirements Analysis で確定する。
- [assumption] 投稿者名は認証がないため手入力または固定値となる想定。
