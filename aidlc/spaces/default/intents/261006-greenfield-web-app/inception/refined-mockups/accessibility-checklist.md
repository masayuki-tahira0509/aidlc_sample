# Accessibility Checklist — 社内お知らせ掲示板

目標水準: **WCAG 2.1 Level AA**。 [Q7=A]
対象: デスクトップ専用単一レイアウト（モバイル固有の達成基準は適用範囲が限定される）。 [Q6=A]

本チェックリストは設計時の作り込み項目であり、完全な適合判定には支援技術を使った手動テストと専門家レビューが別途必要である。 [verification]

## 範囲に関する注記

- Q6でデスクトップ専用を選択したため、モバイル特有の達成基準（1.4.10 Reflow のモバイル文脈等）の優先度は下げる。ただしブラウザズーム 200% での可読性は AA 要件として維持する（1.4.4）。 [Q6=A][Q7=A]
- 色のみに依存しない表現、キーボード操作、コントラスト、スクリーンリーダー対応はデスクトップでも AA を満たすよう設計する。

## 1. Perceivable（知覚可能）

- [ ] カテゴリは色だけでなくラベル文字＋形状でも判別できる（1.4.1 色の使用）。 [Q4=A]
- [ ] 本文テキストは背景に対し 4.5:1 以上のコントラスト（1.4.3）。
- [ ] バッジ・アイコン・入力枠など UI 要素は 3:1 以上のコントラスト（1.4.11）。
- [ ] 操作アイコン（編集✎・削除🗑）には視覚ラベルまたは `aria-label` を付与。
- [ ] ブラウザズーム 200% でレイアウトが破綻せず読める（1.4.4）。
- [ ] 装飾目的のアイコンは `aria-hidden="true"` で読み上げ対象外にする。

## 2. Operable（操作可能）

- [ ] 一覧の全操作（新規作成・編集・削除）がキーボードのみで実行できる（2.1.1）。
- [ ] キーボードトラップがない。モーダルは Escape で閉じられる（2.1.2）。
- [ ] モーダル表示中はフォーカスをモーダル内にトラップし、閉じたら起点要素へ戻す。
- [ ] 全インタラクティブ要素に見えるフォーカスインジケータ（2px・3:1 以上）（2.4.7）。
- [ ] タブ順が視覚レイアウトに沿う（左→右・上→下）（2.4.3）。
- [ ] ドロップダウン（カテゴリ）は矢印キーで移動・Enter で選択・Escape で閉じる。
- [ ] 操作に時間制限を設けない。トーストの自動消滅は操作完了の通知のみで、必須操作を妨げない（2.2.1）。

## 3. Understandable（理解可能）

- [ ] HTML に `lang="ja"` を宣言する（3.1.1）。
- [ ] 全入力に `<label>` を関連付け、必須項目は `aria-required="true"`（3.3.2）。
- [ ] 入力エラーはテキストで内容を説明（赤枠だけに依存しない）（3.3.1）。
- [ ] エラー文は該当フィールドに `aria-describedby` で関連付け、`aria-invalid="true"` を付与。
- [ ] エラー時は修正方法の手がかりを示す（例「タイトルを入力してください」）（3.3.3）。
- [ ] 保存はボタンの明示的操作で行い、自動送信しない。
- [ ] 削除は確認モーダルを挟む破壊的操作の取り消し可能化（3.3.4）。初期フォーカスは「キャンセル」。 [Q2=A]
- [ ] ナビゲーション・ラベルの表現を画面間で一貫させる（3.2.3 / 3.2.4）。

## 4. Robust（堅牢）

- [ ] 妥当で正しくネストされた HTML（開始/終了タグ・一意なID）（4.1.1 相当）。
- [ ] ネイティブ HTML 要素を優先（`<button>`/`<select>` 等）、ARIA は補完的にのみ使用。
- [ ] 動的更新を適切に通知: 一覧読込中 `aria-busy`、エラー `role="alert"`、トースト `aria-live="polite"`（4.1.3）。
- [ ] モーダルは `role="dialog"`/`role="alertdialog"` + `aria-modal="true"` + `aria-labelledby`。
- [ ] ランドマーク: ヘッダー `<header role="banner">`、主要領域 `<main>`。

## コンポーネント別キーボード仕様（WCAG知識ベース準拠）

| コンポーネント | キー操作 |
|---------------|---------|
| ボタン（新規作成/保存/削除/キャンセル） | Enter または Space で起動 |
| カテゴリドロップダウン | 矢印キーで移動、Enter で選択、Escape で閉じる |
| 作成/編集モーダル | Escape で閉じる、Tab はモーダル内トラップ、開く時は先頭入力へフォーカス |
| 削除確認モーダル | Escape でキャンセル、初期フォーカスは「キャンセル」 |

## 検証アプローチ（実装後に実施）

1. 自動スキャン（axe DevTools / Lighthouse）— 問題の約3割を機械検出。
2. キーボードのみ操作テスト（マウス不使用で全フロー完遂）。
3. スクリーンリーダーテスト（NVDA 等）。
4. ブラウザズーム 200% での可読性確認。
5. 色覚シミュレーションでカテゴリ判別が色のみに依存していないか確認。

## Assumptions & Open Questions

- [assumption] 完全な WCAG 適合判定は支援技術による手動テストと専門家レビューを要し、本ステージの設計チェックのみでは保証しない。
- [assumption] モバイル固有基準はデスクトップ専用方針により優先度を下げる。将来モバイル対応時に再評価（NFR8）。
