# Security Test Instructions — 社内お知らせ掲示板

セキュリティテストの手順。認証なし（C1/C2）前提のため、検証の主眼は入力検証・インジェクション対策・XSS対策・CORS設定。自動セキュリティスキャンはスコープ外とし、手動確認と既存単体テストでカバーする。 [security-requirements]

## 1. 入力検証（サーバ側） — 既存テストでカバー

- `AnnouncementServiceTest` / `AnnouncementControllerTest` が必須項目未入力の拒否（400）、カテゴリ許可リスト外の拒否を検証済み。 [NFR-SEC.3][NFR-SEC.5]
- 手動確認: 必須未入力・超長文・不正カテゴリで POST/PUT し、400 とエラー本文が返ることを確認。

## 2. SQL インジェクション対策 — 構造的に排除

- データアクセスは Spring Data JPA の派生クエリ（パラメータバインディング）のみ。文字列連結SQLは存在しない。 [NFR-SEC.4]
- 確認観点: `title`/`body` に `' OR '1'='1` 等を入力しても単なる文字列として保存され、クエリは壊れない。

## 3. XSS 対策 — React デフォルトエスケープ

- 本文は React のデフォルトエスケープで描画し、`dangerouslySetInnerHTML` を使用しない（コード全体で0件）。改行保持は CSS で行う。 [NFR-SEC.6]
- 手動確認: 本文に `<script>alert(1)</script>` を保存し、一覧/詳細でスクリプトが実行されず、文字列として表示されることを確認。

## 4. CORS 設定 — 最小許可

- バックエンドは `http://localhost:5173` のみ許可（ワイルドカードなし）。 [NFR-SEC.10]
- 確認観点: 別オリジンからのリクエストが CORS で拒否されること。

## 5. 秘密情報 — ハードコードなし

- 認証情報・APIキーのハードコードは存在しない。H2 のローカルファイルDBは認証なしの学習用構成。 [NFR-SEC.7]

## 認証なしの前提（受容リスク）

- 本アプリは認証・認可を持たない（C1/C2）。これは明示的スコープ判断であり欠陥ではない。投稿者名は自己申告で本人性非保証（A2）。
- 公開前チェック（将来運用移行時）: TLS化・認証追加・CORS再評価（OQ1）。README に明記済み。 [security NFR-SEC.1][NFR-SEC.9]

## スコープ外

- 自動セキュリティスキャン（OWASP ZAP 等）、依存脆弱性スキャンの常時運用、ペネトレーションテストは本スコープ外（CI Pipeline で軽量な依存チェックを検討可能）。
